# Contributing

Thanks for looking. This is a paper-trading engine on real market data; the
bar for a change is that it stays **correct, real and safe**.

## Setup

Python 3.12, Node 20, and (for browser tests) Google Chrome.

```bash
make install        # backend venv with pinned versions, frontend packages
make check          # lint, types, tests, frontend build, browser tests
```

Or by hand:

```bash
cd backend
python3.12 -m venv .venv
.venv/bin/pip install -c requirements-lock.txt -e ".[dev]"
.venv/bin/python -m pytest tests -q          # offline: the suite fails on network access
.venv/bin/ruff check src tests scripts
.venv/bin/mypy src                           # strict
cd ../frontend && npm ci && npx tsc --noEmit && npm run build && npm run test:e2e
```

`make help` lists every target, including `make demo` (the 25-step acceptance
run on the recorded session) and `make up` (the Docker stack on live data).

## Ground rules

1. **No synthetic market data.** Prices, books and funding come from the
   venues, live or recorded (`hedgelab market record` / `market history`).
   Tests use the committed recordings in `backend/tests/data/`. Pure-arithmetic
   unit tests may type explicit numbers; nothing may *fall back* to invented
   prices.
2. **No live trading path.** No credentials in code, config, tests or history.
   Live adapters are extension points that raise; changing that is a design
   discussion, not a pull request. See [PAPER_TRADING.md](docs/PAPER_TRADING.md).
3. **Never weaken a risk control to make something pass** — hard limits, the
   risk gate, the kill switch, staleness checks.
4. **Every behaviour change ships with a test that fails without it.** For
   invariants, prefer a property test (`tests/unit/test_properties.py`); for a
   bug, a regression test named after what went wrong.
5. **Numbers in docs are measured.** If a change moves a figure the README or
   docs quote, re-run the command that produces it and update the text.
6. **Decimal for money and quantities.** Floats only in the statistics module.

## Layout

The calculation core (`domain/`, `hedge/`, `risk/`, `costs/`) is pure; keep
I/O out of it. Venue-specific behaviour belongs in specs (YAML generated by
`hedgelab instruments sync`) and in `venues/`, never in `if venue == ...`
branches elsewhere. [ARCHITECTURE.md](docs/ARCHITECTURE.md) explains why.

## Pull requests

Small and focused. The template asks how you verified the change and confirms
the safety rules above. CI runs ruff, mypy, the backend suite, the frontend
build and the browser tests.
